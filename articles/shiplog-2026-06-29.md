# Week in Review: Hardened State, Phylax Gates, and a Scriptable CLI

*2026-06-29 — Weekly shipping update*

> Aeon shipped capability tiers, votable skill health tracked as GitHub Issues, and a community-built pre-install security screener — while MiroShark's CLI gained stop, wait, and cost subcommands that make simulations programmable from shell scripts.

## What Shipped

### Aeon gains capability tiers, votable health, and issues-as-state

The biggest architectural change this week landed across five PRs (#547, #548, #550, #552, #553). Three distinct features, all on by default:

**Capability tiers** (#548, 81cc340) restrict what any given skill can do. Skills now declare `read`, `write`, or `full` mode — enforced at the workflow level via `scripts/skill_mode.sh`. Existing skills default to `write` (the old behavior), so nothing breaks; new skills can opt into a narrower sandbox.

**Issues-as-state** (#548, #550) moves the cron state backend from `cron-state.json` commits to a pinned GitHub Issue (`aeon:cron-state`). The default is now `dual` — writing to the Issue AND committing the JSON file, zero-risk migration. The infrastructure to manage this (`scripts/state_store.sh`, `scripts/state_reduce.py`, `scripts/health_issue.sh`, `scripts/health_triage.py`) added +785 lines in #548 alone, spanning `scripts/`, `.github/workflows/aeon.yml`, `.github/workflows/chain-runner.yml`, and every existing skill's `SKILL.md` header.

**Votable health** (#548, #550, fixed by #552) creates a per-skill health issue where operators and contributors can 👍 or 👎 to set repair priority. There was a silent default-off bug: GitHub Actions coerces an unset repo var to `null`, and `null != '0'` evaluates as false — so `HEALTH_ISSUES` unset meant votable health never fired. #552 (db4600b) fixed the gate. #553 (ec6a98a) added the missing `issues: write` permission in chain-runner and fixed var-less skill discovery on the chain path.

### Phylax lands in the skill supply chain

Two PRs from community contributor usephylax add a pre-install security layer to the ecosystem.

`phylax-audit` (#537, 764cd11) is a new skill that returns an **ALLOW / WARN / DENY** verdict on any external skill before you `./add-skill` it. Three independent scans merge into one score: static (prompt-injection patterns, secret exfil), onchain (Base contract checks), and endpoint (x402/API surface). A companion fix (#545, 18792de) wrapped the example threat strings in inline code — without it, content scanners treat the documentation examples as live payloads and flag the skill itself.

`skill-triage` (#544, 0346752) was updated to auto-run phylax-audit dimensions on every inbound skill PR (+66 lines to `skills/skill-triage/SKILL.md`). The verdict now appears before merge, not just pre-install. Also landed: `scripts/validate-config.js` (#546, 297b0be), the shared structural validator that `skills/config-validator/SKILL.md` already invoked as its fast path but was never committed.

### MiroShark CLI becomes automation-ready

Three subcommands shipped to `backend/cli.py` this week:

- `cost` (#208, cef787b) — prints a per-run USD breakdown by phase: `graph_build`, `simulation`, `report`. Useful for benchmarking sim configurations before scaling.
- `wait` (#215, 959aef8) — blocks until the simulation reaches a terminal state, exiting `0` for completed, `1` for failed/stopped, `2` for timeout (+121/-1 lines across `backend/cli.py`, tests, and bilingual docs). The natural automation block: `cli.py wait <id> && process_results.sh`.
- `stop` (#216, ed3cfd0) — cancels a running simulation via `POST /api/simulation/stop`, confirmed in both EN and zh-CN docs (#217, e0811ee).

Community contributor Daniel Andersen (dan-and) landed three robustness fixes: persona-interview hang prevention and error surfacing (#214, 8bbf206), covering engine, worker, API, and UI layers; thinking model robustness (#209, 7a9dffa) — budget tokens, JSON repair, None guards for models that emit `<think>` blocks; and enforced per-round locale in agent actions so non-English simulations no longer drift back to English mid-run (#213, cf0b980). The default model was also switched from `xiaomi/mimo-v2-flash` — delisted from OpenRouter — to `xiaomi/mimo-v2.5` (#207, ec707cd).
