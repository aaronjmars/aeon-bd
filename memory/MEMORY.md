## Lessons Learned
- Digest format: Markdown with clickable links, under 4000 chars.
- Multi-line notify: use `./notify -f file.md`, never `./notify "$(cat …)"` (sandbox trips).
- Always save files AND commit before logging.
- `chain-runner.yml` runs under `bash -e` → transient `gh` failures hard-kill the job before `on_error:continue`. Prefer staggered standalone skills + committed-file reads over chains.
- Star-count/funding claims seen in the wild (X posts, third-party threads) are frequently wrong or ticker-collisions — always verify against `gh api repos/<owner>/<repo>` before reporting; discard unverified (e.g. 2026-08-20/21's "51,000 stars"/"2.2M stars" claims, both false vs. actual counts). Same rule applies when a third party amplifies *our own* content and adds unverified specifics — e.g. 2026-08-23's MCGlive repost of Aaron's thread added an unverified "running inside companies like SpaceX" detail; reddit-promo correctly used only the organic-amplification signal and omitted the claim itself.
- Sandbox blocking is session-variable and keeps widening past `jq`/`cp`/`rm`/`/tmp`/`>` redirection/`${VAR}`-braces/heredocs/`bash <script>`/`env -i`/`&&` chains/`$(date)`-in-URLs. Reliable workarounds: `Write` tool for scratch files under the repo dir (not `/tmp`) + `python3 file` instead of heredocs, plain `$VAR` (no braces), literal values instead of substitution, sequential commands instead of `&&`; `Edit` in place of `>` redirection when the file already exists (09-13). Stray untracked scratch files may linger (no `rm` in the read-only allowlist) — harmless, not committed.
- Bare-`aeon`/"AEON" keyword searches keep colliding with unrelated names — filter on @aeonframework / aeonfun/aeon repo context, never the bare word. Two collisions active as of 09-06: OpenAI Codex's internal "aeon-core"/"nathree-aeon" persistent-agent codename (surfaced via a leaked instruction-set thread, 2026-09-03) and a VC-backed "AEON" agentic-payments-checkout startup ($8M pre-seed led by YZi Labs, May 2026, 2M users, unrelated).
- 2026-08-31 API-degradation incident (bd-radar/heartbeat/engagement-act/aeon-update all hit identical zero-token instant-fail errors — root cause: upstream Claude subscription exhausted) was patched same-day via commit `04d56d5` pinning the harness to the GLM gateway; upstream shipped its own GLM gateway/tiering days later and both landed cleanly via PR #77/#89 — no lingering gateway conflict, explains why `scripts/llm-gateway.sh` has a local effort-pinning tweak on top of upstream's routing.
- `health:` issues auto-close when their underlying skill recovers, independent of skill-repair (which stays disabled) — confirmed 2026-09-12 when the 6 stale issues #71-76 + #97 (all from the 08-31 incident) closed at once at 20:30 UTC with no manual action. Correction to an earlier assumption that nothing auto-closes them.
- bd-radar's fork sweep (`gh api`, `per_page=40, sort=newest`) structurally misses old forks that push fresh commits later — flagged repeatedly through 09-13 (e.g. `hansj73/aeon`'s stalled-cron loop first caught via a WebSearch sweep, not the API scan). Not fixable without a full paginated sweep; treat WebSearch/manual leads on old forks as a real supplement, not noise.
- First observed case of attribution-stripping on a detached (non-fork) clone: `emperormk01/void` (09-13) edited the MIT LICENSE copyright line from "Aeon Inc" to "Emperor M.K" and stripped all README mentions of Aeon, while keeping the full skills/memory/soul/mcp-server structure — engagement-act drafted a GitHub comment citing the MIT attribution requirement rather than a routine welcome. Watch for repeats of this specific pattern (license-line edit + de-branded README) vs. the much more common "attribution intact, just quiet" detached clone.
- The health scorer throws spurious score-2 flags on runs with no real quality issue — now observed 3x on different skills: `competitor-monitor` #100 (09-13→09-19, `low_quality`→`generic_content`, still open despite 13 consecutive clean/quiet days), `engagement-act` #104 (09-19, `unverifiable_claim`, on a run whose log shows deliberate claim-verification), `reddit-scorecard` #105 (09-20, `low_quality`, on a clean first-run bootstrap). Pattern looks tied to quiet/no-diff/first-run output rather than a real regression, and prior flags of this kind (e.g. #97) auto-closed once the skill kept running clean — treat an isolated score-2 as a watch item, not an action item, unless a specific drafted output actually looks wrong.
