# xAI prefetch `to_date` off-by-one excludes today's posts

## Symptom

`reply-maker` emitted `REPLY_MAKER_EMPTY` on two consecutive days (2026-06-18,
2026-06-19). Each day the prefetch cache `.xai-cache/reply-maker.json` was
freshly populated (12 candidates) but **every candidate was from the previous
day**, with a clean cutoff at midnight:

- 2026-06-19 run (17:20 UTC): all 12 candidates `2026-06-18T15:34–23:59Z` → 17–41h old.
- 2026-06-18 run (18:16 UTC): all 12 candidates `2026-06-17T22:00–23:xxZ` → 18–20h old.

All candidates were past both the 6h reply window and the 12h fallback, so the
skip gate dropped 100% → 0 replies.

## Root cause

`scripts/prefetch-xai.sh` built the search window as
`from_date=$YESTERDAY, to_date=$TODAY` and passed it to the `x_search` tool.

The xAI docs say the range is "inclusive of both dates," but the **observed
behavior** is that a date-only `to_date` is interpreted as the instant
`to_date 00:00:00Z`. So `to_date=2026-06-19` ends the window at June 19 00:00Z
and returns **only June 18 posts** — the exact clean-midnight cutoff seen on
both days. This is deterministic, not stale cache: the prefetch runs and
populates correctly, but the window can never contain a post from the current
day. Because reply-maker runs at 17:20 UTC, yesterday's newest post is already
~17h old → guaranteed empty.

Not reply-maker-specific: `fetch-tweets`, `agent-buzz`, `refresh-x`,
`narrative-tracker`, `content-performance`, and `bd-radar` all passed
`to_date=$TODAY` and silently missed today's posts. reply-maker is the canary
because it is the only one with a hard ≤6h recency gate.

## Fix

Push the upper bound one day forward: add a `TOMORROW` var and use it as the
default `to_date` (and at the three explicit call sites). Safe under either
reading of the docs — if `to_date` excludes its day, this now includes today;
if it is truly inclusive, it only adds an empty future day.

`scripts/prefetch-xai.sh`:
- `to_date="${4:-$TODAY}"` → `to_date="${4:-$TOMORROW}"`
- reply-maker `@handle` branch, `content-performance`, `bd-radar`: explicit
  `$TODAY` → `$TOMORROW`.
